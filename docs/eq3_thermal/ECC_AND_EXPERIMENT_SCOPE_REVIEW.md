# ECC 与实验逐项核对（2026-09-20）

核对对象：整合分支 a1cec9f 的实际源码、four-topology-system-v1 冻结输入、DONE/分析收据。本次局部修改仅增加 ECC+迁移的能力拒绝检查及测试，不更换温度、能量、重试曲线或控制参数。所有热结果仍是 CONDITIONAL_SIMULATED，P2旧失败、400K域和盲测状态不变。

## 1. 当前 ECC 是什么

实际消费者：`ecc_cost_proxy.ReadCostProxy` → `ecc_service_adapter.ReliabilityCausalService` → `run_causal_point.execute` → 完整热网络。基础60点走 `run_system_point`，没有启用此代理。

上一窗已观察的 HBF array 最热 die 温度按 Arrhenius 关系累积逐栈等效年龄：

`age30 += dt * exp(Ea/k * (1/303.15 - 1/T))`。

预期额外读取次数为条件插值：

`r = transfer * [2*(PE/1000) + (3.5 + 3.5*(PE/1000))*(age30_days/90)^p]`，
`p = ln((19.9-4)/10.5) / ln(365/90)`。

首次取得服务资源时冻结该请求成本，实际媒体工作倍率为 `1 + round(1000*r)/1000`；媒体与逐栈解码器竞争共享资源。额外物理读取产生能量，有效载荷在 fabric 只交付一次。降温不清除已累积年龄，已提交工作的完成时间不追溯更改。

| 参数 | 当前值 | 证据与限制 |
|---|---:|---|
| Ea / k | 1.04 eV / 8.62e-5 eV/K | HeatWatch旧MLC代理；其20–70°C拟合域外时间单列 |
| ECC参考温度 | 303.15 K（30°C） | 与维护模型85°C参考不同，不可直接相加年龄 |
| 允许年龄 / P-E | 0–365等效天 / 0–2000次 | 当前代理输入域，越域报错 |
| 已跑ECC初始状态 | 90等效天@30°C、1000 P/E、300 K | 情景假设；本轮并非新鲜权重 |
| transfer | 已跑0与0.1；1仅是允许候选 | 不代表置信区间或HBF标定 |
| 锚点 | 365天@30°C、2000 P/E，19.9次额外重试 | Park等旧48层TLC；不是OCP/SanDisk HBF实测 |
| 解码供给 | 新鲜媒体上限的2倍；固定附加延迟0 | 稳态重叠工程假设，不是实测tECC |
| 物理读能量 | array40 + base10 pJ/B | 用户确认包络；base含代理ECC工作，不重复计能 |
| 错误概率、UECC、随机重试尾部 | UNKNOWN | 未运行真实ECC码字解码，不能给HBF错误率或ECC p99预测 |

科学解释：高温保持历史可加速电荷损失，更多重试可降低有效供给；但不是每个可纠错错误都要重读，也不是读取瞬间越热必然越慢。读参考电压、写/读温差、已有年龄与磨损都会影响结果。当前模型只保留其中一条条件链路。

主要来源：[Park等 ASPLOS2021](https://arxiv.org/html/2104.09611)、[HeatWatch HPCA2018](https://research.ece.cmu.edu/safari/pubs/heatwatch-3D-nand-errors-and-self-recovery_hpca18.pdf)。OCP接口语义不提供目标HBF的数值ECC曲线；Sandisk公开性能不能当作该曲线。两个旧NAND来源的温度加速也不完全一致，当前保持原Ea并明确跨器件转用。

### 为什么没有证明节流净收益

相同90天/1000P-E初态，解析恒温比较如下。不是新热运行，不是测量，也没有压缩时间：

| 实际经过时间 | 80°C时预期额外次数 | 85°C时预期额外次数 | 差 |
|---|---:|---:|---:|
| 20 s | 0.90014937 | 0.90024062 | 0.00009125 |
| 1 h | 0.92574993 | 0.94047690 | 0.01472697 |
| 6 h | 1.03014769 | 1.09054124 | 0.06039355 |

20秒差小于0.001工作倍率量化，不能支持显著收益；增加精度也不会把很小的物理差变成大收益。初始0.9额外次数已经使媒体侧理想有效上限从1.536降至约0.808 TB/s，但这一初始成本是所有策略共有，不是本次升温制造的差异。合理目标是比较累计有效交付、队列尾部、恢复、温度暴露与维护代价的折中，不能预先规定某个策略获胜。

## 3. 当前三策略

1. `guard_only`：Light不减少普通请求，Severe/Shutdown未来前台预算为0；恢复后回基准。它也有严重保护，不能称完全无节流。
2. `thermal_hysteresis_guard`：Light预算减至50%；Severe/Shutdown为0；按滞回/驻留恢复。
3. `read_rate_feedback_thermal_guard_v1`：相同严重保护，Light仍受50%上限。按成功交付与积压调未来预算；每步为满供给5%，下限10%，目标容差5%，超过目标10%可减预算。基础速率runner目标为需求与80%供给的较小值（最高1.2288 TB/s/栈）；因果runner读取自己的显式target字段（ECC pilot为1.536 TB/s/栈），两类实验目标不能混报。

反馈不是温度最优控制器：资源忙时保持；门控受限且资源有空闲才增配；加配无交付收益且积压/尾延迟变差可回滚。当前基线未设置p95目标；维护期限可见不等于已优化期限；没有用未来ECC损失预测最佳工作温度。以上数字均为工程策略，不宣称最优。

## 5. 八项消融及 ECC 依赖

因果共同设置：真实tiny-Qwen2 CPU访问结构作为模板，按Qwen2.5重新生成张量/地址/大小，7B权重15,231,233,024B（28层）、72B145,412,407,296B（80层）；不是把小模型时间整体线性放大。上下文4096、batch1、最多4活跃batch，attention/MLP/output各计算bundle1µs，未GPU标定，KV/activation流量不完整。7B需求0.384、72B1.536 TB/s/栈；跨模型不是只改模型大小的单变量对照。

| 消融 | 实际做法/参数 | ECC影响及限制 |
|---|---|---|
| issue vs consumption | 同为单层lookahead预取，分别issue处阻塞或使用处等待；mixed/relay/DASH | 关闭ECC可验证依赖/重叠；固定ECC情景只改变服务代价。不能称真实GPU速度 |
| full vs no coupling | 保留热容/边界/纵向路径；对称删除跨设备区域横向导热边并重建矩阵 | ECC关可隔离热效应；没有删除边后留下虚假散热项；不等于真实独立封装 |
| 有/无刷新争用 | shared与ideal_independent保留相同维护任务、年龄、提交、能量，仅资源竞争不同 | 已跑3对无吞吐差。刷新改善ECC需要共享数据年龄接口，目前不支持 |
| native vs proxy / full vs fast | 前者小原生语义/时序对照；后者须有合格热fast path | 服务对照不能代替热模型精度；fast缺口独立于ECC |
| no prefetch vs prefetch | 按需 vs 一层lookahead；缓存/输入相同；统计提前读取、完成、无用流量 | 可先无ECC；有ECC会改变成本，但不破坏独立消融含义 |
| fixed vs adaptive placement | 同样初始所有源在hbf0；第二次访问触发基本迁移；160GiB有限目的空间，program/erase计费 | 无ECC可验证迁移净代价；与ECC联用缺迁移数据年龄/磨损身份，本轮新增拒绝检查 |
| no page coalescing | 同一tensor并发读取共享全部页 vs各自读取 | 当前仅整tensor相同范围，非任意部分page重叠；无ECC可测物理字节节省 |
| cache capacities | disabled/4GiB/16GiB；真实HBM填充、命中、LRU替换及有限容量；7B模型 | mixed三档，relay/DASH disabled/16GiB；8HBF无HBM不套用。ECC关可测缓存机制；不能把HBM命中算成NAND读 |

ECC影响性能数值不等于使无ECC机制对照失效。独立对照必须成对冻结相同ECC开关，结论标明条件；若要声称长期ECC/refresh收益、跨迁移数据年龄或错误概率稳定性，则必须先补齐对应能力。

## 6. 本次修复、顺序和不能声称的内容

CONFIRMED_BUG：历史ECC+动态迁移未拒绝，逐栈年龄可能被用于错误的数据版本。最小复现先失败（未抛预期异常），修复后明确UNSUPPORTED_COMPOSITION；不替代完整映射实现。完整系统固定测试112通过。曾误指定不存在的测试模块，启动错误原样保留，后使用实际测试发现入口通过。旧ECC8和无ECC矩阵不受此拒绝检查影响，无需为此重跑热求解。

顺序按用户要求：先明确热节流的可辨识问题与参数，再依次非均匀/耦合、预取与issue/consumption、合并/缓存、placement及必要拓扑扩展。不将全部独立实验绑到ECC刷新接口，也不因希望看到收益而放大重试或改写已完成数据。本次交付参数审阅与固定修复，没有启动新的科学矩阵或小时级热运行；既有阶段授权保留，不新增逐点审批。

有根据的下一步是优先考察“相同交付下降温、减少严重停顿或尾部波动”的已可观察收益；对于保持老化净吞吐收益，先检验相同初态下较长实际时间尺度的可辨识性与运行成本，再决定是否值得求解。不能保证某种温控一定胜出。当前过强50% Light限流、目标与ECC有效供给不一致都可能影响结果，但属于待比较的策略设定，不是可随意改掉的程序bug。

原始证据位置：外层工作区 `eq3_thermal/plans/four-topology-system-v1`；本次固定复现/测试在 `eq3_thermal/plans/ecc-experiment-review-v1`。公开源码文档不复制大raw；不把设计索引里的PENDING字段误认作实际已执行状态，实际以运行收据和分析审计为准。
