# 候选 D1:「可信度最大化」评估主线

优化目标声明:本候选的每一处取舍都按用户裁定的判据次序做——第一可信度论证,第二基准化潜力,第三 11 天可行性。温度线的故事地位按裁定降为次要,其影响在 (d) 节如实记录。数字核实等级沿用事实清单的标注([一手]/[转述]/[推断]);事实清单未覆盖、本轮从源文件亲手读到的,标[一手,本轮]。

## 总纲:一句话主线与四个实验

评估章讲一件事:**HBFSim 的注入机制在三种今天买得到的真实介质上被逐点验过,它对 HBF 的数字是同一套被验过的机制加上按规范锚定、明标为投影的参数给出的。** 这是 Quartz(Middleware '15,模拟误差 0.2%–9%,用真实 NUMA 机器当真值验证注入机制本身)与 NOVA(FAST '16,用两个命名档位夹住未知器件)两条被 FAST 社区接受过的路线的合并(brief-3 问题 1e/1b,一手核实的原文在简报内)。四个实验:

- **E1 三介质保真度**(约 1.1 页)——机制可信的证据,评估章基石。
- **E2 保真度的价格**(约 0.6 页)——三模式成本差异与选档指导,正面回答用户对显著性的担心。
- **E3 HBF 服务包络**(约 0.6 页)——核心主张「HBF 带宽是模拟的输出、不是查表可得」,兼基准化论证。
- **E4 dense 与 MoE 在 HBF 上的差别与适用范围**(约 0.4 页)——helpful insight 定位,不与保真度争地位。

另加评估设置与统计口径约 0.3 页。合计约 3 页。

## (a) 四个大实验

### E1 三介质保真度(Tri-media fidelity)

**回答审稿人的哪个问题(审稿人口吻):**「你的六个标定断点误差为零,是因为那六个点本来就是拟合输入。HBF 不存在,你拿什么证明你的模拟器对任何真实器件是准的?你和 Cylon、NVMeVirt 不同,他们手里至少有一台真原型。」

**论证结构(为什么是三种介质):** 单一代理只能证明「对这一台准」;三种介质——U787/6787p 上的 DRAM(约 116.1 ns 实测延迟[推断,同机身份由 docs/36 一处顺带提及推出,Gate 1 未执行])、同机 CXL SSD(微秒级,形态待盘点)、CD8P NVMe vmem 路径(单页 11,133 ns 到 512 页 20.25 ms[一手])——横跨约五个数量级的延迟尺度。同一套注入机制、只换每介质各自标定的 profile,若在三者的 held-out 点上误差都有界,则「机制与介质无关、误差来自参数」这一迁移论证成立,HBF 投影(同机制 + 规范锚定参数)继承机制侧的可信度。这是 (b) 节链条的第 3 环。

**子实验清单:**

- E1.0(前置)U787 能力盘点 = C0 的 Gate 1,原样采纳(lspci/cxl list/daxctl/numactl 清单见 19 号规划 §5.1)。CXL SSD 是 CXL.mem/DAX/NUMA 还是块设备,决定 E1.3 走哪条路。
- E1.1 语义与覆盖表:vLLM token ID 一致、llama.cpp 逐字节相同文本、容量模式 checksum `14245581564465502923` 一致[均一手];覆盖清单(10,339 条覆盖决策、30 条改写指令、0 条不支持指令[一手]);全部按字节而非按 launch 数披露覆盖比例。
- E1.2 每介质「标定/验证分离」的微基准:每介质事前冻结标定集(例:尺寸 1/16/256 页,顺序读,QD 1/8)与 held-out 集(尺寸 4/64/512 页与更大外推点、random/strided/pointer_chase 模式、其余 QD)。CD8P 一侧即 15 号 item 11;U787 两介质一侧即 item 17。held-out 模式集同时补掉弱点 3(随机访问按单页成本计无实测依据[一手])。QD 相关点全部在含 PR #3 修复(211,331→664,995 ns 均值[转述,拉取代理])的冻结快照上跑。
- E1.3 应用级差分 A/B(Cylon 式):同一 GPU 负载、同一页服务路径,三组——DRAM 后备零延迟(纯软件路径对照)、真实介质后备(不注延迟)、DRAM 后备加从该介质标定的模拟延迟;比较 ΔT_HW 与 ΔT_SIM(C0 §5.2 的公式,采纳),报 normalized slowdown 误差与配置排名一致性。

### E2 保真度的价格(Fidelity–cost)

**回答审稿人的哪个问题:**「reference/fast/hybrid 三档如果成本差不多,谁都会用最高精度,你的三档设计就是过度工程。反过来,如果 fast 很快,它的误差是多少?我该在什么规模下选哪档?」——这正是用户 eq2 的担心,原话:「这3个模式运算时间/成本差异会有显著性吗……最理想情况我们可以argue小模型跑最高精度, 大模型跑快速节省时间」。

**已有数字已经证明差异显著,正文直接摆出来:**
- 同一确定性 Qwen3-30B-A3B 用例,reference 44.469 s 对 fast 2.014 s,20.8 倍[一手,docs/proofs/2026-08-11-hybrid-complete.md];且这只是 2,304 次启动里建模 24 次、16 KiB 覆盖下的差距。
- 纯插桩(零建模访问)已慢 37–51%(0.8898 s 对 1.4156/1.8269 s)[一手,docs/proofs/2026-08-11-vllm-timing-adapter.md]——这是任何档都逃不掉的地板。
- 61,064,245,248 字节全量注册在 vLLM profiling 阶段产生数量上不可行的同步请求[一手,docs/proofs/2026-08-11-vllm-exact-live-delay.md]——reference 路径存在硬性的规模墙,不是「慢一点」而是「跑不了」。
- 引用任何含 reference 路径的数字时同时写明 time_scale=100 与 1 的口径差别[转述,spec L420]。

**最小 PoC 设计(回答「差异是否随规模拉开」):** 两个模型规模(TinyLlama F16 与 Qwen3-30B-A3B,两者用例都已存在[一手])× 三档模式,同一注册范围策略,测墙上时间与建模请求数。预期读出一张 2×3 交叉表:小模型上三档都在秒级、reference 可用;大模型上 reference 的墙上时间随建模请求数线性放大(44.5 s 是 24 次建模启动的成本,一整层注册后建模启动数将放大数百倍)。若交叉表印证,则「小模型跑最高精度、大模型跑 fast/hybrid」的选档指导有实测支撑;这张表就是 eq2 的答案。

**子实验清单:**
- E2.1 四类时间拆分(Q3/item 12):零注入对照 + time_scale 扫描,把 164.70x 拆成建模介质延迟与每 warp 请求路径开销;拆不开则限定句原样进正文(大纲已有的退路,保留)。
- E2.2 三档 Pareto:hybrid 的热身请求数(现 1,024)与稳态抽样率(现 1%)各取 3 档,x 轴墙上时间、y 轴 E1 的 held-out 误差,reference/fast/hybrid 固定视觉编码——SMARTS/Sieve 的「误差–加速二维图」范式(brief-2 综合一第 9 条)。
- E2.3 规模交叉 PoC(上述 2×3 表);其中大模型一格依赖 item 14(注册扩到一整层,分批注册避开 profiling 风暴)。
- E2.4 未计时放行访问的影响(item 7):强制开关一组对照,量化 fail-closed 门「值多少」。

**图表(1 张):** 图 3 双联——左:堆叠条形,native/插桩/服务路径/建模四段时间,2 模型 × 3 档;右:误差–时间 Pareto 散点,hybrid 各抽样档标注。20.8x/164.70x 数字标为 emulator execution cost,不是 HBF 投影(README 自注原句照用[一手])。

### E3 HBF 服务包络(HBF service envelope)

**回答审稿人的哪个问题:**「HBF 的参数 OCP 规范都印着,你的模拟器输出的不就是把参数表抄一遍?别人为什么需要你这个平台而不是一张 Excel?」

**核心论点(15 号文件的核心主张,一手):** 规范 Table 2 的 3072 GB/s 是 UCIe 接口值;阵列侧可持续速率取决于规范没给数值的并行读出单元数 N,按 Table 3 组织算出 262.1 GB/s(tR=4 µs)到 52.4 GB/s(tR=20 µs),比接口值低 11.7–58.6 倍。**带宽是模拟的输出,不是查表可得——这既是可信度论证(我们发现了参数表读不出的东西),也是基准化论证(任何评估 HBF 想法的人都需要这个输出)。** 相邻工作恰好各取一个 tR 单值互相打架(FlashAccel 4 µs、Micron 20 µs、TileLens 扫 1–20、li2026 扫 8–30[均转述,brief-1]),我们对 tR 全程扫描并把结论写成条件式(Mnemosyne/Pond 先例,brief-3)。

**子实验清单:**
- E3.1 读出单元数 × tR 二维扫描(item 1/Q10):N 取 256/1024/3,000/15,000,tR 取 1/2/4/5/10/20 µs,报稳态阵列带宽与端到端吞吐。
- E3.2 时序档按规范重新锚定(item 15/弱点 8):conservative/nominal/aggressive 三档对齐规范约 0.4–3.0 TB/s 三个带宽点,配置层动作。
- E3.3 超显存容量点(Q5):110 GiB 逻辑范围 + 2 GiB HBM 缓存、128/128 访问、checksum 一致[一手]——作为「平台能装下别人装不下的实验」的一行证据,限定照抄(不声称 110 GiB 被物理读过)。
- E3.4 基准化交付物清单(文字,约 5 行):冻结的 profile 套件 + 负载 + 参考结果 + 覆盖清单 + manifest 字段(采纳 C0 §1.2 的 benchmarking framework 要件与 §12.3/12.4 的 manifest/CSV 规范,压缩到 artifact 说明里)。

### E4 dense 与 MoE 在 HBF 上的差别与适用范围(helpful insight)

**回答审稿人的哪个问题:**「你验完了保真度,那这个平台能告诉我一件我原来不知道的事吗?比如业界都在说 HBF 是给 MoE 的,是不是真的、到什么程度?」

**我们的独有增量(brief-1 综合判断,原文一手核实于简报):** TileLens 的 trace 是真的但时序是模拟的;li2026 与 Micron 的专家行为全靠假设(li2026 连专家驻留策略都没交代);**没有一层对照点是在真实执行中带真实专家路由测出来的。我们有:真实执行里哪些专家真被激活、专家权重何时被读、读了多少字节,不需要假设。**

**子实验清单:**
- E4.1 批大小/并发对稀疏红利的侵蚀(item 3/Q11):真实路由轨迹下,专家并集覆盖率与权重流量随实际 decode 并发变化,与独立均匀路由零假设 `1−(1−k/E)^B` 对照(公式只作基线,C0 §8.6 的口径采纳:横轴用实测 active sequences 不用配置上限)。已有推算表(批 1 触及 6.2% 专家/72.3 tok/s 到批 128 触及 100%/4.5 tok/s)[一手,paper/37,自标全部是推算]作为预测,实测轨迹去检验它。
- E4.2 可预测性结构:全专家注册轨迹里每 token 884,736 次页访问、仅 384 页(0.04%)真正不可预测[转述,prefetch-accuracy-sweep artifact]——报为轨迹级结构性事实;预取精度扫描(上限 5.99x 等)仅作 modeled 标注引用。**不写任何运行时快慢结论**(投机预取运行时收益主张已撤回,门槛照守[转述,paper/36:76])。
- E4.3 dense 对照:至少一个 active-compute-matched 的 dense 运行做每 token 权重字节量对照(C0 §8.4 的双基线要求,受时限压缩为一个,另一个进 limitations);与 TileLens 那句「Qwen 因 MoE 路由始终 memory-bound、Llama 在 batch 256 转 compute-bound」[转述,brief-1]及 li2026 大 MoE ΔE2E +280–285% 对小 dense +184.1%(带非单变量限定与容量账缺口限定,文档 44 规矩)[转述,brief-1]做外部对照。

**图表(1 张):** 图 5 双联——(a) 专家并集覆盖率对实际 decode 并发,实测轨迹曲线对零假设虚线;(b) 每 token 权重流量,dense 对 MoE,随并发。图注给出适用范围结论的条件式表述:MoE 的流量优势存在于并发低于某阈值的区间,阈值由实测轨迹给出。

## (b) 微基准到宏观负载的论证链条

这是用户点名没想清楚的问题(原话:「我们做了很多micro benchmark, 但是如何用这些Micro benchmark来论证我们的实验的模拟器是准确的? 我还没想好」)。答案是一条五环的链,每环有自己的证据形态,环与环之间的传导方式写死,不许跳环。

**第 0 环(前提):机制与参数分离。** 审稿人对「模拟不存在的器件」的根本疑问是:你的数字里哪部分可能错?把可能错的东西切成两类——注入机制(PTX 改写、覆盖门、时序服务、页路由)与介质参数(延迟曲线、带宽、队列行为)。机制可以对真实器件验证,参数对 HBF 只能是投影。这是 Quartz 的写法(机制在 NUMA 真值上验到 0.2%–9%,参数明说是投影[一手核实,brief-3 1e]),也是 FAST '20 Empirical Guide 教训的正面回应:Optane 一代模拟失真的根源不在参数取值错,而在「器件就是慢一点的 DRAM」这个结构性假设错[一手核实,brief-3 问题 2]——所以机制侧的验证必须覆盖结构性行为(尺寸非线性、模式差异、队列、饱和),不是只对一个平均延迟。

**第 1 环:微基准之内,标定与验证分离。** 证据形态:每介质一份事前冻结的标定集/验证集划分(写进 artifact 的 manifest,拟合脚本物理上读不到 held-out 数据),正文只报 held-out 误差(中位数、P95、最大),标定点在 parity 图上以空心点出现并在图注写明「拟合输入,不计入误差」。现有六断点零误差从此在论文里只承担「实现没把表读错」这一句话的功能(proof 文档自述照抄[一手])。微基准的设计原则照 brief-2 综合二第 1 步:每个微基准让单一机制主导——尺寸扫描测曲线形状、模式扫描测突发重置假设(直接检验弱点 3)、QD 扫描测排队(PR #3 后)、工作集扫描测缓存转折(Cylon 的归一化 r = 工作集/有效缓存)。

**第 2 环:跨介质迁移。** 单介质 held-out 通过只证明「这条曲线拟合得好」;三介质(DRAM/CXL SSD/CD8P)同机制、异参数、都通过,才证明「机制不携带介质私货」。证据形态:一张三介质误差汇总(图 1c),外加一句可检验的陈述——三介质的 held-out 误差同量级(可对照 CXLMemSim 的 7.85%–13.19%、FEMU 微基准 0.8–11.6%、MQSim 合成负载 2.9/4.9% 这些先例量级[均一手核实于 brief-2])。迁移到 HBF 的论证句式:「HBF 的数字 = 被三介质验过的机制 + 规范锚定的参数;参数不确定性用三档 profile 夹逼(NOVA 先例)加 tR 全程扫描(TileLens/li2026 先例)显式呈现,结论写成条件式。」明确写出这个论证的边界:迁移保证的是机制不引入系统性偏差,不保证 HBF 介质没有我们三种代理都没有的结构性行为(Empirical Guide 的 256 B 内部粒度就是这种例子[一手核实,brief-3]),这一句进 limitations,并列出「真器件到手后哪些结论会先倒」的清单(brief-3 套路 4)。

**第 3 环:微观误差到宏观主张的传导——测,不算。** 不做解析误差传播(访问重叠、并发掩盖使解析传播不可信),改为直接在 held-out 应用上测端到端:E1.3 的差分 A/B 给出应用级 normalized slowdown 误差与配置排名相关性。证据形态:ΔT_SIM 对 ΔT_HW 的差分对比(不比 raw wall time,C0 问题 D 的诊断采纳),加 Spearman 排名相关(Accel-Sim 先例:对基准工具,排名保真与单点误差同等重要[一手核实,brief-2])。传导规则写成措辞门槛表(采纳 C0 §6.8 的门槛数值:微基准中位误差 ≤10%、P95 ≤20%、宏观 ≤15%、排名相关 ≥0.90):绝对误差达标 → 定量主张;只有排名达标 → 趋势/排名主张;都不达标 → 只保留部件级标定主张,E4 的 insight 相应降格。**每个应用级数字旁边标注它走到了哪一档。**

**第 4 环:准确性买到了什么。** 链条的收尾定式(brief-2 综合一第 6 条,6/10 篇先例这么做):E3 与 E4 只有在 E1/E2 通过后才有资格出现,正文里用一句话把这个依赖写明。这样评估章的四个实验不是并列的四块,而是一条链:机制被验过(E1)→ 验过的机制付什么价、怎么选档(E2)→ 用它读出参数表读不出的东西(E3)→ 用它测出别人只能假设的东西(E4)。

## (d) 与 C0(19 号规划)的差异点清单

1. **实验数量从「3+1 个 EQ、EQ1 内含 A–E 五个子实验、每子实验数十个扫描点」压到硬性 4 个大实验。** C0 的 EQ1-B 一项就要 8 尺寸 × 5 模式 × 3 状态的矩阵,EQ1-C 再乘 8 档 QD——11 天内由合作者一人执行不可行(第三判据)。D1 用「事前冻结的小标定集 + 小 held-out 集」替代全矩阵:验证的说服力来自 held-out 纪律与跨介质迁移,不来自点数(SMARTS 的立场:小单元大置信优于大覆盖[一手核实,brief-2])。
2. **三介质迁移论证是 D1 新增的、C0 没有的主轴。** C0 §4 有 reference hierarchy 表,但其 EQ1 实验本质上单代理运行;D1 把 DRAM/CXL SSD/CD8P 三点横跨五个数量级这一事实升格为链条第 2 环的正式论证(第一判据:这是「机制可信」最强的一条证据,也是我们对 Cylon「只有一台原型」的差异化)。
3. **温度(C0 的 EQ4)从评估章整体移出,不再「有条件保留」。** C0 留了闭环达成即保留的门;D1 直接判:11 天内从 0 命中的运行时代码做到「闭环 + 硬件校准 + held-out」不可行,且本轮裁定明言温度是次要考虑。影响如实记录:论文若在标题/摘要/挑战里保留 C3(温度),评估章将没有对应实验,故 D1 连带要求把 C3 降为讨论一节的初步能力(−8.10%/−3.72% 两套数字取哪套的未决项[一手,16-questions #8]随之出评估章)。这是 D1 相对大纲现状最大的一处改动,属于写作层取舍,需用户拍板。
