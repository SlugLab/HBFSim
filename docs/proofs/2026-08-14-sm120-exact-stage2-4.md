# SM120 exact Stage 2--4 proof checkpoint

Date: 2026-08-14 UTC

This checkpoint closes the repository's Stage 2--4 implementation and proof
gates on one NVIDIA RTX PRO 6000 Blackwell Server Edition (CC 12.0, driver
595.84, CUDA 13.0). `exact` is a fail-closed label for a frozen AOT module,
environment, nominal clock pair, calibrated workload vector, deterministic
output oracle, and successful post-run checks. PTX does not expose undocumented
NVIDIA physical-channel identities, SMSP scheduling, or scoreboard state, and
HBFSim does not claim otherwise.

## What is modeled

- Ordinary global load, store, and supported atomic RMW instructions create a
  shadow future at the original instruction. The pass waits at the first proven
  register consumer or ordering drain, snapshots store data at issue, forces
  acquire/acq_rel/volatile atomic ordering even when the return value is unused,
  and rejects ambiguous CFG/def-use cases.
- TensorMap descriptors are shadowed when the runtime creates, copies, or
  updates them. Each dynamic tile address is classified against explicit
  registered HBM/HBF ranges; static PTX is never used to guess a descriptor's
  backing space.
- TMA emulation covers tiled 1D--5D load/store, im2col variants, multicast,
  typed OOB fill, TF32 conversion, mbarrier phase reuse, and bulk async groups.
  The live correctness suite covers OOB, but the current exact post-run gate is
  intentionally in-bounds-only and rejects nonzero OOB bytes.
- Four load/fanout and two store/return queues are calibrated,
  contention-equivalent per-SM resources. They are not physical GNIC2TEX or
  GPCARB channel identities. Runtime SM/warp/cluster observations are routing
  inputs, not stable physical SMSP identities.

## Stage 2 and Stage 3 live correctness

The Stage 2 harness compares native, synchronous-control, timing-future, and
capacity-future execution for ordinary loads, stores, atomics, vectors,
branches, source reuse, and fences. Its acquire litmus discards the result of
`atom.global.acq_rel`, accesses an independent address next, and requires a
nonzero runtime ordering wait. Every path must be bit-exact, conserve futures,
and finish with zero unsafe launches, faults, or leaks.

The Stage 3 harness covers 27 TMA/TensorMap scenarios and 81 native/timing/
capacity runs, including dynamic HBM/HBF splits, descriptor replacement,
im2col, two-CTA multicast, typed OOB fills, cold/warm capacity, and writeback.
It requires byte-identical outputs and conservation of issue, fanout, and
HBM/HBF/OOB bytes with no stale descriptor generations.

## Exact microbenchmark and real-workload boundary

The one-shot sideband probe is the exact ordinary-load microbenchmark used by
both adapters. It is the calibrated `train-ordinary-load-four-warm` vector:
128 threads (four resident warps), depth 8, 384 iterations, load/use distance
32, 12,288 registered bytes, and 393,216 issued loads. Inputs are generated
deterministically and every one of the 128 output checksums is compared with a
host oracle before exact finalization. A mismatch cannot be merged into a
workload result. The request ring is sized to the maximum 1,024 simultaneously
live futures. Its 10-second request deadline is a liveness watchdog with enough
headroom for the profile's complete 1,024-request reference warmup; modeled
latency still comes from the selected timing profile and calibrated queues.

TinyLlama and Qwen run their model graphs natively and compare deterministic
semantic outputs. Only after or outside the opaque graph does the isolated,
content-bound AOT probe run under the exact owner. The records therefore say
`model_graph_fidelity: "native"`, `model_storage_registered: false`, and
`exact_scope: "one_shot_sideband_probe"`; they do not relabel opaque framework
kernels as exact.

This split is necessary for the selected Qwen fused-MoE path because it uses
legacy `cp.async`, which is neither a Stage 2 ordinary LD/ST/atomic operation
nor a Stage 3 TensorMap/TMA operation. Supporting that graph exactly would need
a separate semantic transform, manifest class, calibration class, and live
correctness proof.
