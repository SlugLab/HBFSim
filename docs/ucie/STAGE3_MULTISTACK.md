# UCIe Stage 3 CPU multistack interface

Stage 3 builds on the [single-device Stage 2 frontend](STAGE2_DEVICE_COALESCING.md). A parent process validates complete original read spans and canonical backing identity before it splits them into 64 B AXI read packets. One child process per stack owns one real MQSim engine and one central event loop for all that stack's modules. Each module has its own UCIe link and 36-bit local AXI address; a 512 GiB stack has 16 modules of 32 GiB each. The four-stack reference has 2 TiB of continuous global *placement*, while media allocation and event engines remain distinct per stack.

The top input is [the strict Stage 3 schema](../../configs/schema/ucie-multistack.schema.json). Its single `total_capacity_bytes` divides exactly across stacks and modules; `total_service_bandwidth_bytes_per_s` divides exactly across stacks and sets each worker's one aggregate media service cap. The default [2 TiB reference](../../configs/profiles/ucie/hbf-stage3-4x512gib-top.json) uses four stacks, 16 modules/stack, x64 UCIe at 16 GT/s, and a **scenario assumption** of 512,000,000,000 B/s total (128,000,000,000 B/s per stack). This cap is separate from actual AoU flit/credit accounting and is never multiplied by a blanket link efficiency. The named media and link files are resolved relative to the top configuration file; the media file is read into a per-worker effective copy, never rewritten. The reference link's AR/R initial credits, propagation, and admission depth remain explicitly labeled scenario assumptions. OCP NCDU is 1/2/4/8/16 and each bank has two 4 KiB device buffers. The OCP Figure 4 bank example is 16 banks/die; reduced bank counts are research fixtures. The AoU v0.8 Appendix D HBF profile is marked *under development* in that specification.

An HBF bank uses one native MQSim chip with one native die and plane as an internal service resource. HBF host channel, core die and bank identity is retained separately from native channel/chip/die/plane. This models independent bank sense and channel sets without claiming physical equivalence to an HBF die or all internal Figure 4 buses. The frontend queries read-only FTL mapping before submission and checks the actual `COMMAND_ISSUED`, `MEDIA_BEGIN/END`, `DATA_OUT_BEGIN/END`, page, bytes, and bank from the native observer. It does not change MQSim's FTL, scheduler, old SATA/NVMe path, or public host ABI.

The parent and all workers use one integer-ns simulated time coordinate. At each horizon the parent exchanges all known inputs, advances every worker no further than that horizon, processes results and shared-link events, and repeats same-time feedback until quiescent. `advance_until(h)` leaves `h` open for a caller to consume, cancel or submit at `h`; the parent closes it only before moving to `h+1`. Each worker has independent MQSim singleton state. IPC and operating-system scheduling time do **not** contribute to modeled device latency. The 1 ns stepping is a conservative correctness implementation and can be expensive for large traces; it is not an HBF clock or CDC model.

Original registered bytes, unique canonical accessed bytes, accepted/actually delivered 64 B AXI payload, upstream and per-module AR/R wire bytes, real 4 KiB media submissions, and native command counts are separately reported. Unique bytes use `(canonical_id, generation, endpoint_id)` identity: aliases of the same object deduplicate, other objects, generations and endpoints do not. This diagnostic interval accounting is exact until its fixed 4,194,304-interval software limit; after that `unique_canonical_exact=false` and dropped-span count are explicit, so an exact-closure result cannot claim PASS. Host reassembly reserves one 64 B packet per child at parent admission, dispatches worker children incrementally, and consumes a worker R once the real downstream has entered that finite host allocation. A slow application retains host capacity and backpressures later parents without inventing a third device bank buffer. A permanently too-large single read raises an input error; temporary occupancy returns backpressure.

Worker IPC has bounded length, sequence and stack checks, finite wall-clock exchange deadlines, and a 24-hour idle receive guard. That idle guard is an engineering process-lifetime bound, not a modeled read deadline; a production service with a longer inactive period must recreate its worker session or configure a different supervised lifetime before use. A worker crash reaps the exact owned workers and exposes one `BackendError` result for each accepted, unconsumed parent. If a caller has already consumed a stable complete result when an ACK fails, that result remains delivered once and the remaining session is poisoned. Software cancel/deadline does not generate a hardware cancel packet; in-flight AR/R and media drain in normal operation.

Stage 3 supports only a validated regular read translated to 64 B AXI packets. It does not implement writes, bursts, PHY training, CRC/retry, ECC, physical page-buffer circuitry, the full HBF internal bus, or production GPU/host-daemon integration. AoU granule/flit packing and credit timing are modeled, but this is not a complete bit-level AoU codec. The old daemon's `MqsimOnlineEngine(Profile)` behavior is checked separately; passing the old path must not be described as live new-UCIe GPU coverage.

The exact CPU reproduction entry is [the Stage 3 script](../../scripts/reproduce_ucie_stage3_cpu.sh). Its ordinary `full` mode builds all default CPU targets and runs CTest; `focused` runs Stage 3 and nearby real-MQSim checks. Explicit `capacity-one` and `capacity-four` modes instantiate MQSim geometry for 512 GiB per stack in one or four worker processes; observed RSS was about 4.1 GiB per worker, so these modes require measured RAM margin. Raw results and limits are in the [Stage 3 CPU checkpoint](../proofs/2026-09-29-ucie-stage3-cpu.md).
