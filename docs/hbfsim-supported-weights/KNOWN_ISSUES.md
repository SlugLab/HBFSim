# Failure cases to preserve when reproducing the run

These findings explain the validated configuration. They are not a request to modify the PTX load/store rewriting algorithm. Keep original failed or partial runs alongside successful successors.

| Failure / misleading observation | Established cause or boundary | Reproduction action |
|---|---|---|
| A native kernel is registered but has no modeled accesses | Registration does not replace its executed function. The old partial CUDA12 path bypassed exact native auto-binding and used host-symbol resolution. Some selected functions are LOCAL or have no matching exported FUNC symbol. | Use registered entry identity, current fatbin generation, exact original CUfunction and authenticated native auto-binding. Do not rely on nearest ELF symbol names. The original five-of-eight result stays partial. |
| A correct output is labeled full coverage | Native fallback can return correct output while selected weights remain unmodeled. | Verify exact storage ranges, address-matched modeled launches, active module service completion, output equality and counter closure separately. |
| The pass generates PTX successfully but all native parameters become scalars | The old `0ab365…` pass lacks the successful CVTA-aware pointer metadata inference. The correct `62b6e8…` DSO had been copied into a different build directory; that directory's current source/object files do not describe the copied binary. | Rebuild the actual CVTA metadata source component and validate native pointer classifications. A successful transform exit code or matching current source trees is insufficient. Do not overwrite the frozen successful stage with the failed reproduction candidate. |
| A reconstructed core compiles against old headers | Selected-file patch validation omitted capacity/API declarations used by the copied context implementation. Separately, new coverage metadata changes C++ object layout. | Include the complete matching core/public-header source set, not a handpicked subset. Compile gate and its static core against the same coverage header. |
| A gate rebuild exports different CUDA identities | The successful standalone link uses a CUDA symbol-version script and explicit dependencies absent from the old default CMake target. | Preserve and verify actual link options, versioned exports, runtime-domain routing and dependencies. |
| CUDA12 launch forwarding reaches CUDA13 runtime handling | Compiler/header version and runtime forwarding domain were conflated in earlier failures. | Keep explicit CUDA12 entry lookup and ABI handling. CUDA13 compilation of HBF components does not change the framework's runtime domain. |
| A norm path faults under the original optimization choice | The validated configuration uses O0 for the exact joint-norm raw module; the prior optimized failures remain in the archive. | Retain the narrowly scoped raw-hash optimization policy. Do not generalize it to all kernels or change memory rewriting to conceal the failure. |
| Extension loading fails before session creation | The launch omitted the explicit vLLM extension path. | Preflight the selected extension/core pair and set the extension path explicitly. |
| Framework JIT selects an incompatible compiler | The system CUDA12.4 nvcc is not the successful compiler for this architecture. | Pin the CUDA12.8 toolchain and FlashInfer nvcc selection. |
| A fresh CUDA13 configure fails although an older build directory exists | Current glibc math declarations and the CUDA header disagree on the `rsqrt/rsqrtf` exception specification. Selecting G++13 alone did not resolve the fresh compiler-identification failure. | Use a separately versioned compatibility-header overlay, preserve the original toolkit, and verify a fresh minimal compile before the full build. Record the overlay and actual compiler commands; do not bypass compiler validation or substitute old generated helpers and call it a clean build. |
| Copying the final stage directory breaks native provenance | Native binding rows still reference source-package raw/staged files and scoped sidecars. | Preserve the dependency layout or regenerate all affected paths, hashes and provenance joins consistently. |
| Old MoE fixture stages are combined with the current model | The real short model produced four raw variants, with two distinct parameter counts. | Use the actual model cache and verify each raw/entry/ABI identity; do not reuse the earlier two-variant fixture. |

The source reconstruction v1 patch was rejected because it omitted required headers. Its v2 successor verified the complete selected core tree. Neither patch application nor a CPU build alone proves inference coverage; a newly assembled runtime must be validated before its results are equated with the original run.

The successful generated norm stage and runtime pass DSO are separate artifacts. A late-loaded runtime library's path must not be used to infer which library produced a prestaged module. This distinction is essential when reconstructing the original experiment.

The CUDA header diagnosis is supported by the actual local compile failure and the previously used CUDA12.8 compatibility overlay. A [matching NVIDIA forum report](https://forums.developer.nvidia.com/t/cuda-headers-in-crt-math-functions-h-still-broken-in-debian-13-repo/362708) is supporting context, not validation of the local repair. The original CUDA13 toolkit remains pinned; an upgrade is not silently substituted.

## Reproduction entry fixes

The first extracted runner wrote native command receipts under `command_argv` but its staged baseline check read only the older `command` field. Historical-result replay could pass while a newly produced baseline would fail. The corrected reader accepts the canonical new field and the legacy field; a CPU check now constructs a new-style native receipt and passes it through the same validation.

Resolving every configured path through symlinks can silently discard the intended Torch/vLLM overlay or CUDA toolkit view. File content hashes should follow the target bytes, but PYTHONPATH and CUDA_HOME must retain the configured lexical paths. The corrected runner separates those responsibilities and checks all eight checkpoint/config/tokenizer files against their saved identities.

A clean bpftime clone also needs its recursive pinned submodules before CMake configuration. The first fresh configuration failed at missing libbpf; the successor initialized and verified all 20 recursive gitlinks and then built successfully. Merely carrying the top-level source patch is insufficient.

The gate's CPU fake-runtime fixture initially passed a synthetic CUDA function handle into a real driver, causing a fixture segmentation fault. Later incomplete fake-library lookup returned CUDA status 35. The successful fixture isolates both runtime domains and provides an inert driver mapping; these failed fixture attempts are retained separately and do not establish a production gate failure.
