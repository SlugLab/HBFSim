## 三个运行模式与已有成本数字

- reference = 在线 MQSim,只取其闪存介质模型(mapping、事务调度、NAND 时序、排队、通道),绕过 NVMe/PCIe/SATA/驱动层。[转述,HBFSim/README.md:31-34、102-105]
- fast = GPU 设备侧模型,自旋等待 %globaltimer;两个子模型:参数化(src/cuda_runtime/device/hbf_device.cu:413-423)与实测曲线(:364-374)。[转述]
- hybrid = 默认档:前 1,024 个请求 + 每类新访问的第一次 + 稳态 1% 抽样走 reference,其余走 fast。[转述,docs/superpowers/specs/2026-08-09-hbfsim-hybrid-design.md §9.3]
- fast 对 reference:同一确定性 Qwen3-30B-A3B 用例 2.014352 s 对 44.469 s,相差 20.8 倍,两次 token ID 完全一致。README 自注:「These wall-clock ratios characterize the emulator, not projected HBF hardware.」[一手,docs/proofs/2026-08-11-hybrid-complete.md 经大纲 35 转录]
- reference 验证默认 time_scale=100,负载运行默认 1;这是 164.70x 头条数字的来源之一,引用时必须写明。[转述,spec L420]
- 纯插桩开销(0 次建模访问,全部 61,064,245,248 字节注册成功但 PTX 改写未激活):基线 0.8898 s 对 1.4156 s / 1.8269 s(慢 37–51%)。[一手,docs/proofs/2026-08-11-vllm-timing-adapter.md 经大纲 35 转录]
- 带时序注入(16 KiB 覆盖,2,304 次 fused_moe_kernel 启动中建模 24 次):基线 0.269996 s 对 44.469084 s,观测减速 164.70x;建模介质延迟与每 warp 请求路径开销合并报告,拆分是待做工作。[一手,docs/proofs/2026-08-11-vllm-exact-live-delay.md]
- 全量注册 61 GB 不可行:vLLM profiling 阶段产生数量上不可行的同步请求。[一手,同上]
- 两条路径之间目前没有任何一致性检查代码;大纲已三处许诺「可检验的一致性」。[转述,16-questions #4]
- reference 路径介质参数在 SSD_Device 构造时设定、之后无法更改,因此无法跟随温度;只有 fast 路径能。[转述,16-questions #3]
