# Isolated EQ3 interface status

Status in this table distinguishes code wiring from successful end-to-end
execution. Parameters labeled scenario assumptions are not device calibration.

| Interface | Actual producer | Actual consumer | Enablement | Current capability and evidence | Remaining gap |
|---|---|---|---|---|---|
| Campaign configuration and arrivals | `experiments/eq3_maintenance/campaign_inputs.py` | `run_point.py`, then `ClosedLoopCoordinator` | Explicit CLI point only; no default change | Four topology configs, 16 MQSim dies per HBF stack, finite working region, W1/W2 arrivals and explicit energy coefficients | Conditional engineering inputs; capacity, link parameters and energy decomposition are not product calibrated |
| Foreground MQSim admission and completion | `MaintenanceMqsimService`, inherited `try_submit()` / `until()` from `scripts/eval/mqsim_service.py` | `closed_loop.py` | Isolated maintenance binary passed explicitly | Same process owns foreground and maintenance. Raw MQSim callback must equal reported completion before fabric composition; otherwise `UNSUPPORTED_COMPOSITION` | No arbitrary raw/reported overlap composition; live host/GPU path is not connected |
| Native command activity | Experimental MQSim command observer in `backend/service/hbf_mqsim_maintenance_service.cpp` | `ActivityEnergyLedger.native()` and the `native` timeline | `--native-command-observations on` through the client | Real phase, command/transaction identity, physical placement, bytes and foreground/background/maintenance parent facts | Coefficients remain engineering assumptions; unknown placement is rejected rather than inferred |
| Parametric HBM media | `tools/eq3_basic_hbm.py::BasicHbm` | Coordinator, `ActivityEnergyLedger.hbm()`, fabric source-ready | Only topologies with explicit HBM config | Bounded HBM source buffer, media start/end and bytes feed the same time axis | Parametric FIFO is not a real DRAM backend; HBM die placement and array energy distribution are explicit assumptions |
| Two-bank package fabric | `tools/eq3_basic_fabric.py::BasicFabric` | Coordinator final delivery, energy ledger, resource probe | Explicit scenario config; default off | HBF direct/relay and HBM GPU-link events, bounded source/partner banks, per-pair resources; final fabric completion is the sole delivered-byte fact | Link latency/bandwidth/energy are uncalibrated; external GDDR service remains unavailable |
| Activity-to-energy | Native events, HBM media facts and fabric start events | `experiments/eq3_maintenance/energy_ledger.py::ActivityEnergyLedger` | Explicit engineering energy profile | Disjoint NAND media, NAND data-out, HBM array, fabric endpoint and prescribed GPU scopes; window `[start,end)` component joules | No fabricated standby/ECC/retry energy; coefficients do not support product J/GB claims |
| Energy-to-temperature | `ActivityEnergyLedger.flush(boundary)` | `thermal_client.py::ThermalService.advance(start,end,component_energy)` | Explicit persistent full 2 mm thermal process | Complete component energy is consumed in contiguous 20 ms windows; entity temperatures and memory-stack guard states return to coordinator | First Q1 attempt correctly failed a stack-state coverage mismatch before a successful closed loop. The wrapper repair and a complete process run were pending when this table was written |
| Thermal guard and rate policy | Thermal service produces stack states; coordinator produces completed-window delivery, p95, backlog, resource and maintenance facts | `read_rate_policy.py::ReadRatePolicy`, then `ByteTokenLedger` | Profile `enabled`; policy arm explicit. Module default is off | P0 ignores Light but shares Severe/Shutdown; P1 consumes explicit hysteresis caps; P2 only raises a future budget when the gate limits and observed backend/resource facts show idle capacity. Shared endpoints are deduplicated and charged atomically after successful admission | Retry/UECC remain UNKNOWN unless observed. Policy benefit has not been established by a completed closed-loop campaign |
| Resource observation | Native/energy intervals plus `BasicFabric.resource_state()` in `run_point.py::resource_probe` | P2 policy window facts | Optional injected probe | Half-open window backend busy fraction and instantaneous fabric ownership; absent facts stay `None` | Current probe is an engineering measurement adapter, not an MQSim scheduler API; its first full-run behavior remains to be validated |
| Native maintenance lifecycle | Isolated maintenance engine/service emits DUE/QUEUE/read/program/commit/retire/fail and native transactions | `MaintenanceMqsimService`, coordinator timeline and native energy ledger | Explicit maintenance jobs; experimental binary only | Same MQSim engine/resources as foreground; due/deadline, physical target, version/mapping commit, failure and age-reset facts preserved. Severe/Shutdown delay new maintenance submission while time/cooling continue | v11 A/B proves maintenance-off foreground noninterference only. Review found non-monotonic PPA-token versioning and missing GC pin protection; generation+pin and a real concurrent-write test are in narrow repair, so final maintenance correctness is not yet established |
| Closed-loop event horizon | `closed_loop.py::ClosedLoopCoordinator` | `run_point.py` | Explicit construction | Advances to arrival, MQSim/HBM/fabric work, thermal window and maintenance due/completion; completion/release precedes control then same-time admission. Submitted work drains in full thermal windows; unsubmitted work is censored | `CONNECTED_IN_CODE_AWAITING_SUCCESSFUL_PROCESS_RUN`; the failed Q1 first attempt is retained rather than counted as a completed loop |
| Output contract | Coordinator and activity ledger | `run_point.py` JSON/CSV writer | Per point | One time base for request/native/fabric/HBM/thermal/rate/control/maintenance/resource/energy facts; observation and drain work are separate; p95 components and censored backlog retained | Paper-ready aggregation and four-topology completed receipts do not yet exist |
| Acceptance v3 | Existing canonical sensor CSVs and energy receipts | `tools/eq3_acceptance_v3.py` | Retrospective CLI only | Integer-ns, independent sample grids, source-precision quantization intervals, one directed crossing extraction and global matching; definite misses/timeouts fail and ambiguity never passes | Retrospective diagnostic, not a replacement for frozen v1/v2 or a qualified spatial reference |
| Process-level noninterference | Default service binary and isolated v11 binary in separate processes | `backend/tests/test_ab_process.py` | Explicit fixed test | PASS for 8-stack/1-die (24 requests) and Q1 4-stack/16-die (12 requests), exact 0 ns comparison of foreground lifecycle/native placement/old stats; each process links one engine archive | Applies to v11 with maintenance off. It must be rerun for the repaired maintenance binary and does not prove maintenance-on correctness |
| External GDDR and live GPU | No service producer | Identity/limit reports only | Unavailable | Q4 may model package-only HBF requests and prescribed GPU heat | External GDDR service, board heat/temperature feedback, token rate and live GPU validation remain `UNAVAILABLE` |

The actual v11 process A/B evidence is
`eq3_thermal/plans/isolated-maintenance-campaign-v1/points/AB-PROCESS-01/`.
The current fixed software checks pass 13 policy, 7 coordinator and 11
acceptance-v3 cases. These checks validate contracts, not the pending full
closed-loop process result.
