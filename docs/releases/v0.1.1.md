# v0.1.1 — UCIe multistack interface

This release brings the current UCIe implementation into the public HBFSim
source tree. The host request interface connects registered accesses to AXI
read transport, multistack routing and the real online MQSim media backend.

## Implementation changes

- Configurable link, device and multistack profiles with typed validation,
  independent per-stack service limits and bounded request admission.
- Backing-range registration, page striping, request coalescing and exact
  completion reassembly across stacks.
- Event-driven MQSim advancement, shared-memory worker transport, ordered
  admission, compact completion batches, completion waves and deferred worker
  startup. These are host software mechanisms; media service and modeled delay
  remain separate from emulator wall time.
- An explicitly selected daemon backend and vLLM placement/binding support.
  Nominal and zero-injected-wait modes both execute MQSim; zero mode changes
  the injected wait rather than replacing simulated service.
- Build targets, configuration schemas, fixed CPU tests and reproduction
  scripts for the interface. UCIe is optional and defaults to off.

The [UCIe documentation](../ucie/README.md) describes the actual interfaces,
configuration, selection flags and reproduction entry points. The
[release CPU checkpoint](../proofs/2026-10-06-ucie-release-cpu.md) records the
source provenance, build commands and raw validation results for this release.

## Build from the tag

```bash
git clone --branch v0.1.1 https://github.com/SlugLab/HBFSim.git
cd HBFSim
git submodule update --init --recursive third_party/bpftime third_party/mqsim
cmake -S . -B build-ucie -G Ninja \
  -DHBFSIM_ENABLE_CUDA=OFF -DHBFSIM_ENABLE_MQSIM=ON \
  -DHBFSIM_ENABLE_UCIE=ON -DBUILD_TESTING=ON \
  -DCMAKE_DISABLE_FIND_PACKAGE_PkgConfig=TRUE \
  -DCMAKE_DISABLE_FIND_PACKAGE_CUDAToolkit=TRUE
cmake --build build-ucie --parallel 4
ctest --test-dir build-ucie --output-on-failure -R '^ucie_'
```

The ordinary quick start in the [README](../../README.md#quick-start) continues
to build the default backend. The optional interface has its own tests and
configuration namespace under `configs/profiles/ucie/`.
