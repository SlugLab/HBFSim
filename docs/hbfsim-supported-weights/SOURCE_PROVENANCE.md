# Integrated source provenance

This integration starts from GitHub main `17d0fc58c0444789650ab40b4641802b5b6c2db8`. The experiment working branch was not a fast-forward of main; its unrelated thermal changes are not imported.

The HBF source package includes the successful core/public-header changes, adapter weight selection and automatic PTX preparation, access-accounting support and scoped native launch gate. The gate must compile against the matching coverage headers and core implementation. Copying the gate alone onto the older header layout is not a valid reproduction.

The parameter metadata implementation in `src/ptxpass_hbf/plugin.cpp` is the actual CVTA-aware source used to generate the successful normalization manifest (source SHA `887f01f41ca914895bd6206cbb3397a8a250fe6609cc54c015a2d8c3786c0b3f`). An older runtime pass library classified those pointer parameters as scalars; its apparent build-directory source was not evidence of the later copied generator binary's origin. The recreated pass reproduced the successful pointer classification and manifest exactly.

The integration does contain historical device-helper changes relative to upstream main. Those are preserved successful experiment source, not a new memory-rewrite design in this reproduction step. The two device helper files match the frozen successful source byte-for-byte; see [DEVICE_HELPER_SOURCE_IDENTITY.json](evidence/DEVICE_HELPER_SOURCE_IDENTITY.json).

The bpftime integration is the complete patch from clean `ec26daecc8e787fb80fd95dd596a576404a5e36e`, stored at `patches/bpftime/0002-supported-weights-from-ec26.patch` (SHA `63f4820fa41bdf6538ec45d805f3c68e3dea9a3e605ffbd65f3b88788c51121f`). Apply it once to that clean revision. Do not apply the earlier partial patch first: it overlaps this complete patch. The recreated agent source's 16 changed/added files matched the successful agent source, and 20 recursive submodule gitlinks were pinned and checked clean before the successful build.

The original native PTX collector and scoped provenance join are preserved under `tools/native_ptx_reproduction/`. New build paths and private generated symbol names may change binary/PTX hashes. Hashes must be regenerated from actual artifacts and linked consistently; copying historical hash expectations onto new bytes invalidates provenance.

## Aggregate parameter generator is a distinct successful source

Embedding and Fill were generated by historical pass `c3e581cde814bdee52a0a374943f56a74285fb3c2a7364912ccd37179cadeeb2`, whose actual plugin source SHA is `a7f538d38b33e5bc709e200d517fe724daf5def37db602fa6e817c8df744dad3`. The [original aggregate-pass build receipt](evidence/ORIGINAL_AGGREGATE_PASS_BUILD_RECEIPT.json) records its exact compile/link inputs. It adds aggregate pointer-field metadata inferred from constant parameter loads followed by conversion to a global address. It does not change the memory-op rewrite or device helper algorithms.

Normalization's CVTA-aware generator alone is insufficient evidence for those aggregate arguments. Reproduction must record the generator identity for each raw module and preserve `pointer_fields`, `fields_complete` and `opaque_reason`. The old aggregate generator linked the system CUDA12 runtime, distinct from the new CUDA13 runtime profile. That distinction belongs in the separate generator build recipe.

For Torch's full PTX members, the conservative automatic preparation path can reject unrelated module-level calls such as `__assertfail`. The successful selected-entry transformation used a scoped/direct pass and explicit provenance. Preserve that scope; do not remove assertions or silently mark an entire module supported. Fill's raw diagnostic reports three parameter-space loads as unsupported opcodes, while its HBF-relevant count excludes those explicitly identified non-HBF loads. Raw diagnostic counters and scoped admission fields must remain distinguishable.
