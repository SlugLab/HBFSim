### 三句话说清评估章怎么论证模拟器可信

1. **机制与参数分开验证。** 注入机制(PTX 改写、覆盖门、时序服务、页路由)在今天买得到的真实器件上按「标定集/留出集分离」验出有界误差(E1);HBF 的每个数字 = 被验过的机制 + 按规范锚定、全图明标为投影(projection)的参数。这是 Quartz(Middleware '15,机制对真实 NUMA 参照验到 0.2%–9% 误差,参数明说是投影)[一手核实于 brief-3 1e] 的写法。
2. **每个引擎有自己的硬件锚,措辞按事前注册的门槛表分档。** 实测曲线档由 CD8P 留出点(含 GPU 发出子集)锚定;MQSim 档由 QD 配对扫描(F4)与三档同流缝合(F5)锚定;应用级主张由走交付路径(容量页服务路径)的三臂差分(E1.3)锚定;每个应用级数字旁标注它落在门槛表(中位 ≤10% / P95 ≤20% / 宏观 ≤15% / rank ≥0.90 且 n≥10 [一手,C0 §6.8])的哪一档,达不到就降档措辞,不删实验。
3. **准确性买到了别人给不了的东西——这就是基准化论证。** 被验过的机制重演已发表论文互相打架的器件假设(E3:公开文献 tR 相差 5 倍、带宽相差约 17 倍 [一手核实于 brief-1 综合判断]),并用真实专家路由检验假设驱动方法哪里会得出错误结论(E4);以论文命名的器件档案套件 + 冻结轨迹 + 参考结果 CSV 作为一等交付物进 artifact,后续任何 HBF 论文选参数时,这张图是现成的定位坐标系。

### E1 机制保真(Mechanism fidelity)——约 1.1 页,基石

**回答审稿人的哪个问题(审稿人口吻):**「你的六个标定断点误差为零,是因为那六个点本来就是拟合输入。HBF 不存在,你拿什么证明注入机制对任何真实器件是准的?你的真值是什么?被验证的到底是哪个引擎——产 HBF 数字的那个,还是另一个?」

**正文呈现纪律:** E1 含 6 个子块(E1.0–E1.6,E1.0 不进正文),必须写成一个实验的子结构(小节内分段),不得写成并列实验——否则违反用户「4 个大实验」逐字上限。

**子实验:**

- **E1.0 第 0 天闸门 + Snapshot B(不进正文,进方法节一句话)。** 四项闸门:①epsilon 档验证——构造全参数取最小合法值(如 read_latency_ns=1 ns)的配置档作零延迟对照臂,实测其残余建模时间,≤111 ns(单页实测 11,133 ns 的 1%)即接受(profile 校验拒绝的是 ==0 不是小值,src/profile/profile.cpp:330 [一手,核查报告 §3]);②F2 backing 脚本验证——容量模式后备是调用方给的文件路径,机制上可指任意设备,缺的只是选择脚本 [一手,核查报告 §7 EQ2 行];③F7 time_scale=1 复测 reference 基准点(reference 验证默认 time_scale=100,是 164.70x 头条数字的来源之一 [转述,spec L420]);④hbf_mqsim_bench 的 channels/dies/planes 字段对「并行读出单元数 N」的语义映射探针(该工具已有 --bytes/--pattern/--arrival-gap-ns [一手,核查报告 §7 EQ1-B 行])。并行执行 Gate 1(U787/6787p 能力盘点,lspci/cxl list/daxctl/numactl 等,清单见 C0 §5.1 [一手],不阻塞主线)。item 7 强制放行开关等全部运行时小改一次性合并为 Snapshot B(第 2 天冻结),此后分析侧离线脚本(留出切分、误差计算、绘图)不触碰运行时、不引发重跑(F6)。
- **E1.1 语义与覆盖。** vLLM token ID 逐位一致、llama.cpp 确定性文本一致、容量模式 checksum `14245581564465502923` 一致 [均一手,docs/proofs/2026-08-11-hybrid-complete.md 与 vllm-exact-live-delay.md];覆盖统计(10,339 条覆盖决策、30 条改写指令、0 条不支持 [一手,vllm-exact-live-delay])按字节而非按 launch 数报覆盖比例(按字节统计当前未实现 [一手,核查报告 §7 EQ1-A 行],划归论文侧分析脚本);PR#4 覆盖语义在冻结快照上验证 [一手,核查报告:PR#4 经 80fd29c 集成,936b8e5 补跨行 PTX 扫描]。超显存 110 GiB 一行证据放这里,限定照抄(不声称 110 GiB 被物理读过 [一手])。
- **E1.2 CD8P 加密标定/留出。** 12 个尺寸(1/2/4/8/16/32/64/128/256/384/512/768 页)顺序读:原 6 断点(1/4/16/64/256/512)保留为标定集(parity 图空心点,图注写明「拟合输入,不计入误差」);模型冻结后新采的离网格点(2/8/32/128/384/768)为**唯一承重留出集**,其中 768 页把「512 页之外全是外推」的区间实测化、单独报告不并入留出汇总;留出集内含一个 GPU 发出的子集(经真实 PTX 改写路径,hbf_vmem_sequential 用例链路已存在——proof (2) 六断点即此形态 [一手,项目 CLAUDE.md 第 4 节(2)]),这是 NVMeVirt/FEMU 填任何 profile 都产不出的证据形态。random/strided 模式**不进留出集**、改入「特征化集」:模式类模型无自由参数(随机等访问一律按单页 11,133 ns 计,无实测依据 [一手,事实清单标定现状]),误差可事先算出(−74.8% 量级 [一手,cd8p-vmem-tuning 常数页模型 64 页误差]),照测照报为模型的已知适用边界,门槛表不对其生效;配负载侧论证:本文负载未命中流由专家内连续页主导,884,736 次页访问中仅 384 页(0.04%)不可预测 [转述,prefetch-accuracy-sweep artifact]。预处理协议(顺序写满 + SMART 写入历史入 manifest,照 MQSim/Amber 先例 [一手核实于 brief-2 §4 与 brief-4 (b)])+ 重测一个 2026-07-30 标定点作漂移对照。3/3 重切分降为稳健性附注;模型族见过全数据在方法节如实声明。

- **E1.5 跨引擎缝合(F5)。** 同一容量未命中流(JSONL)喂 fast/hybrid/mqsim 三档,报逐流偏差——回放引擎已支持 `--mode fast|hybrid|mqsim` 吃同一份未命中文件,基础设施只差一次运行 [一手,核查报告 §3];另加半件:同一请求流喂 MQSim 原生全栈配置对我们的截段适配器,报偏差(砍序①,触发则转 artifact 复算项)。

## 2. 微基准怎么论证模拟器可信:完整论证链

回答用户原话「我们做了很多 micro benchmark,但是如何用这些 Micro benchmark 来论证我们的实验的模拟器是准确的?我还没想好」。链条五环加一个前提,每环写清证据形态与先例出处;环与环之间的传导方式写死,不许跳环。

**第 0 环(前提):机制与参数分离。** 把「可能错的东西」切成两类:注入机制(可对真实器件验证)与介质参数(对 HBF 只能是投影)。先例:Quartz(Middleware '15)在真实 NUMA 机器上验证注入机制复现已知延迟的能力(0.2%–9%),参数明说是投影 [一手核实于 brief-3 1e];FAST '20 Empirical Guide 的反面教训——Optane 一代模拟失真的根源不在参数取值错,而在「器件就是慢一点的 DRAM」这个结构性假设错(判决原句「all of these emulation methodologies are inaccurate」;真器件 256 B 内部粒度;RocksDB 结论在真器件上反转)[一手核实于 brief-3 问题 2]——所以机制侧验证必须覆盖结构性行为(尺寸非线性、模式差异、排队、饱和),不是只对一个平均延迟。

**第 1 环:校准/验证分离(E1.2)。** 证据形态:事前冻结的标定集/留出集划分写进 artifact manifest,拟合脚本物理上读不到留出数据;正文只报留出误差(中位/P95/最大);标定点空心、留出点实心;六断点零误差降格为「实现没把表读错」一句话。先例:MQSim 用微基准反推真 SSD 内部参数、验证前预条件化两个 4 小时阶段 [一手核实于 brief-2 §4];Accel-Sim 38 个微基准喂自动调参器后另设验证集 [一手核实于 brief-2 §5];brief-2 综合二第 1 步「每个微基准让单一机制主导」。

**第 2 环:跨器件/跨引擎锚点(E1.2 GPU 子集、E1.3、E1.4、E1.5)。** 单器件留出通过只证明「这条曲线拟合得好」;要写死**哪个引擎被哪个锚锚定**:实测曲线档←CD8P 留出(含 GPU 发出子集);MQSim 档←F4 QD 配对(硬件排队真值)+ F5 同流缝合偏差 + 原生全栈对照;应用级←E1.3 三臂差分(走交付路径)。方法节放一张显式映射表(哪个实验锚定哪条路径)。DRAM 不作保真腿,只作开销地板(116.1 ns [推断,机器身份未盘点] 低于 37–51% 插桩地板 [一手]);范围论证:HBF 的 tR 是 1–20 µs 域 [一手核实于 brief-1],亚微秒验证不是 HBF 主张所需。先例:MQSim 四块匿名真 SSD 的 QD/请求大小验证 [一手核实于 brief-2 §4];NVMeVirt 对四类真实设备 ≤12.2% 且先证「仿真质量优于 FEMU」再谈保真 [一手核实于 brief-4 (a)];Ganger FAST '02(目标设备不存在时把服务时间与仿真器开销分开)[转述,C0 §17——**需按 verify-paper-sources 核原文**];Cylon 的 NAND 延迟置零控制臂 [一手核实于 brief-2 §1]。

**第 3 环:误差地图(特征化集,E1.2)。** 不假装全域有效:random/strided 按单页计的已知偏差(−74.8% 量级)照测照报,写成「在哪些尺寸/模式/QD 区间可信、哪些区间只能定性」的地图;负载论证(0.04% 不可预测 [转述])说明承重维是顺序保真。先例:CXL-DMSim 显式给出中间区间的模型误差来源(C0 §3.6 引述 [一手,C0]——**该文未亲读,引用前需核原文**);FEMU 主动报误差随并发复杂度增长并归因(单线程单 plane 0.7% → 16 线程 16 plane 38%)[一手核实于 brief-2 §3]。

**第 4 环:应用级留出差分(E1.3)。** 微观误差到宏观主张**测,不算**(访问重叠使解析传播不可信):ΔT_SIM 对 ΔT_HW 的差分对比 + Spearman 排名相关,不比 raw 墙钟(C0 问题 D [一手])。措辞按门槛表分档,每个应用级数字旁标它走到哪一档。先例:Cylon 用 normalized slowdown 与定性趋势通过 FAST(全文没有一个百分比误差数字 [一手核实于 brief-2 §1]——这是最坏落点的底);Quartz 的机制验证写法同上;FEMU 宏观 0.5–38% 被接受的量级语境 [一手核实于 brief-2 §3]。

**第 5 环:排名保真(E1.3 排名 + E3-c)。** 对基准工具,「拿它做比较会不会做反决定」是别人引用时真正消费的性质。证据形态:排序相关一律报 n 与精确置换 p;≥0.90 门槛只对 n≥10 生效;全体引擎对 tR 单调时的一致是平凡的,这句告诫进图注。先例:Accel-Sim 相关系数 >0.97 + §VI 两个「基线不准则设计结论翻转」案例 [一手核实于 brief-2 §5];Sieve 把相对精度单独立为评估维度 [一手核实于 brief-2 §10];SMARTS 的「可量化置信」表述(hybrid 抽样档若谈误差界的出处)[一手核实于 brief-2 §6]。

**链条收尾定式:** E3/E4 只有在 E1/E2 之后出场,正文一句话写明依赖(brief-2 综合一第 6 条:6/10 篇先例以「先证准,再证准了才看得见的东西」收尾 [一手核实于 brief-2])。链条的诚实面(6/10 篇主动声明真值缺陷 [一手核实于 brief-2 综合一第 7 条]):六断点是构造出来的确定性检查、端到端 vmem 档不是介质档、随机模式无实测依据——全部正文自述。

## 4. 对用户三个关切的直接回答

### (a) 三模式成本差异显著性

**已有数字已经显示差异巨大:** 同一确定性 Qwen3-30B-A3B 用例,基线 0.269996 s、fast 2.014352 s、reference 44.469084 s(164.70x),fast 对 reference 20.8x [均一手,hybrid-complete 与 vllm-exact-live-delay];而这是只建模 24/2,304 次启动、16 KiB 覆盖下的差距。**但这些数字有一个必须先排除的测量假象:** reference 验证默认 time_scale=100 [转述,spec L420],20.8x/44.469 s 两侧的口径无记录(缺,合作者清单第 1 条)。因此 F7(time_scale=1 复测,半天)是 E2 的先决闸门,任何图表与措辞在它之前不写。

**最小 PoC 设计:** 同一 vLLM 适配器、同一模型,覆盖 3 档(16 KiB/单专家/可行最大)× 三模式,画建模请求数 × 墙上时间。若曲线分叉,选档指导有实测支撑;用户设想的「小模型跑最高精度、大模型跑快速」在证据上落地为「低建模请求数跑 reference、高建模请求数跑 fast/hybrid」——载体从模型规模改为覆盖档,因为换模型会同时换适配器、不可归因(红 1 D1-4 裁定),这一点要向用户说明。

**坍缩分支也预写好了(论题不死):** 若 time_scale=1 下差距坍缩,选档论据换轨到三个与 time_scale 无关的实测事实——37–51% 插桩地板 [一手]、61 GB 全量注册在 profiling 阶段产生数量上不可行的同步请求 [一手]、reference 逐请求同步路径的覆盖-成本线性放大。

### (b) 6787p 物理介质怎么用进主线

用户逐字:「你要用6787p上的物理设施(如cxl ssd, or dram)等真实物理介质来模拟Hbf因为真的还没出来」。处置分三步:

1. **第 0 天 Gate 1 能力盘点(并行,不阻塞主线):** 命令清单在 C0 §5.1 [一手];机器身份目前是 [推断](Xeon 6787P、256 GB DDR5-6400、实测延迟 116.1 ns、Smart CXL Module,由 docs/36 一处顺带提及加 CXLMemSim 写法推出 [推断,事实清单]),须合作者确认(合作者清单第 3 条)。
2. **按盘点结果分角色:** CXL SSD 若呈现 CXL.mem/DAX/NUMA 形态→E1.3 三臂差分的第二设备臂 + 第二条标定曲线(跨器件机制迁移论证的加分项);其上 DRAM→epsilon/开销地板臂——**不能当保真腿**,因为 116.1 ns 级目标低于 37–51% 插桩地板 [一手],逐请求注入在此尺度测出的是开销不是模型误差(红 2 D1-3,蓝队 CONCEDED);若只呈现块设备→按 F3 阻塞语义回放对照,或主线落 CD8P 单设备。
3. **报告义务:** Gate 1 任何结果都须如实报告用户——约束在 Gate 1 失败时只部分满足,这是显式闸门而非静默丢弃(裁判第七节)。

### (c) dense/MoE 洞察实验放哪、怎么写

**放哪:** E4,倒数第一个实验,约 0.4 页,符合用户「倒数一个二个实验……helpful insight」的逐字定位。

**怎么写才不与保真度争地位,五条:** ①开头一句话「本节结论依赖 E1 验证过的机制,误差界随 E1」,定位为链条收尾的能力展示(brief-2 综合一第 6 条的定式 [一手核实于 brief-2]);②证据形态是计数事实(哪些专家真被激活、权重何时读、读多少字节),不是时序预测——这是相邻三层先例(TileLens trace 真但时序模拟、li2026 与 Micron 专家行为全靠假设)共同缺的那一层 [一手核实于 brief-1 综合判断];③结论写成条件式适用范围(「MoE 的流量优势存在于并发低于某阈值的区间,阈值由实测轨迹给出」),不写绝对判断;④外部锚点全部带限定引用(li2026 按文档 44 六条规矩);⑤预取一切数字标 modeled/trace-level,运行时收益禁写(E9 禁令 [一手,核查报告 §1])。翻转测验的框架让它同时反哺可信度故事(Accel-Sim §VI:不准的基线导致错误设计结论 [一手核实于 brief-2 §5])而不占保真度的证据位。
