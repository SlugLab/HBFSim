3. 新 Evaluation Questions
============================================================

删除旧主问题：

“reference / fast / hybrid fidelity-cost trade-off”

不是完全删除数据，
而是不再作为主要 Evaluation Question。

三种模式的 runtime/cost
放 reproducibility / appendix table。

新的主线固定为：

EQ1:
Can HBFSim faithfully reproduce observable GPU-side
delay effects and flash-storage service behavior on
available hardware?

EQ2:
Does HBFSim preserve asynchronous GPU memory semantics,
particularly issue-completion overlap for TMA and
deferred global-memory accesses?

EQ3:
Under what combinations of media parallelism,
media latency, and fast-tier residency is HBF useful
for LLM inference?

EQ4:
How do model sparsity, serving concurrency,
and prefetching shift that HBF feasibility boundary?

5. GDDR7 的定位
============================================================

当前 GPU 的实际显存是 GDDR7。

禁止：

“GDDR7 validates HBM”
“GDDR7 emulates physical HBF”

正确写法：

GDDR7 provides the physical GPU execution substrate
for validating address-range dispatch, PTX/SASS
instrumentation, latency injection, critical-path
placement, and asynchronous execution semantics.

可以建立：

native logical range
fast-tier logical range
HBF logical range

但这是 logical treatment，
不是物理介质等价。

如果当前 architecture 不支持同 kernel 多 profile，
允许同 benchmark 分别运行三次，
唯一改变 range/profile。

优先避免大改架构。

8. EQ2: Async/TMA semantic fidelity
============================================================

首先审计：

feature/sm120-exact-stage1

是否已经正确实现本实验需要的：

issue now
complete later
wait only when necessary

正确 oracle：

issue time = t_issue
modeled media latency = D

t_complete =
    t_issue + D

程序在 issue 后执行 independent work W。

到真实 synchronization/consume point 时：

residual =
    max(0, t_complete - t_wait)

理想情况下：

residual =
    max(0, D - W)

禁止 async op 在 issue 时直接支付完整 D。
