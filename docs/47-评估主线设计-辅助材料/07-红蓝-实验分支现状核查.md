# 候选 D2:基准化最大化的评估主线

优化目标(用户逐字裁定):「主要考虑是如何论证我们模拟器可信! 如何成为别人之后测试, 论文测试的基准!」。D2 的中心押注:**让每一篇后续 HBF 论文在选器件参数时都绕不开我们**。实现手段是把「可信度论证」和「基准化」焊成同一件事——先用物理介质把注入机制的误差钉死(可信),再把已发表 HBF 论文互相打架的器件假设装进这个已验证的执行框架里逐一重演(基准化)。别人以后写 HBF 论文,要么用我们的器件档案套件,要么解释为什么不用。

核实等级沿用事实清单标注:[一手]/[转述]/[推断]。

## 总骨架:4 个大实验与 3 页分配

| 编号 | 名称 | 页数 | 支撑的判据 |
|---|---|---:|---|
| E1 | 物理介质锚定的标定与留出验证 | 1.0 | 可信度(第一判据) |
| E2 | 三模式成本拆账与选择指南 | 0.5 | 可信度 + 回应 eq2 担心 |
| E3 | 已发表 HBF 假设在同一执行框架下的重演 | 0.9 | 基准化(第二判据),兼 dense/MoE 素材 |
| E4 | 真实专家路由下的 dense/MoE 适用范围 | 0.4 | dense/MoE 洞察(约束要求的倒数实验) |
| 方法与统计口径小节(公平性契约、真值声明、重复次数) | — | 0.2 | 可信度 |

合计 3.0 页。E3、E4 是倒数两个,其中 E4 是纯 dense/MoE 洞察,E3 的结论层也按 dense/MoE 分开报(见 E3 图 2),满足「倒数一到两个是 dense/MoE 洞察」。

贯穿三个实验的一条主张链(D2 独有,C0 没有):**E1 证明绝对误差有界 → E2 证明高保真模式贵 → E3 证明便宜模式在已发表假设的对照上给出与高保真模式相同的排序**。对基准工具,排序保真是交付物——Accel-Sim 的先例是逐计数器相关系数 >0.97 与「不准的基线会得出错误设计结论」的两个翻转案例(brief-2 §5,[一手核实于简报]);Sieve 把「相对精度」单独立为评估维度(brief-2 §10)。审稿人由此得到的结论不是「这个模拟器误差 X%」,而是「用它的快速档做 HBF 设计比较,决定不会做反」——这正是别人拿它当对照基线的前提。

## (a) 四个大实验

### E1 物理介质锚定的标定与留出验证

**审稿人问题:**「你说的数字凭什么信?器件不存在,你的真值是什么?」

**真值声明(写进正文第一段):** 两个物理锚点,各管各的主张。CD8P(Dell DC NVMe CD8P E3.S 1.92TB,PCIe 5.0 x4,普通 NVMe 端点,不是 CXL 端点 [一手])验证「注入机制能复现一条实测的闪存服务路径」;6787p 上的物理介质(CXL SSD 或 DRAM,实际形态待 capability inventory 确认 [一手,19 号规划 Gate 1 未执行])验证「注入机制能复现一个已知的、可控的目标延迟」。两个锚点都不是 HBF,这句限定照抄仓库纪律写进正文。

**子实验:**
- E1-a 语义与覆盖:vLLM token ID 逐位一致、llama.cpp 确定性文本一致、容量模式 checksum 一致(`14245581564465502923`),加覆盖统计表(建模/无注册范围/不透明/拒绝四类计数)。全部已有数字。
- E1-b 标定/留出切分(15 号 item 11,blocking):现有 6 断点里取 3 点(如 1/16/256 页)重新拟合,其余 3 点(4/64/512 页)作留出点报误差;再在 CD8P 上新采不在原网格上的尺寸(如 8/32/128/384 页)与随机、反向模式各 11 样本——随机模式是弱点 3(随机访问按单页 11,133 ns 计,无实测依据 [一手])的正面处理。
- E1-c 6787p 已知延迟复现:在 6787p 介质上实测一条访问延迟曲线,配成 profile 喂给 HBFSim,再在同一负载下对比注入结果与实测——Quartz 的先例:用真实存在、延迟已知的参照验证注入机制本身,报 0.2%–9% 误差(brief-3 问题 4 第 1 条,[一手核实于简报])。
- E1-d 未计时放行的影响(15 号 item 7,blocking):加一个强制放行开关,对照 fail-closed 与放行两种运行的报出时间差,给「拒绝执行」这个设计一个数值。
- E1-e 注入点敏感性(item 9)与缓存命中高估上界(item 10):各做一个小对照,结果进限定段,不单独成图。

**图表:** 图 1 三联:(a) CD8P 实测与模型的 parity 散点(标定点与留出点不同标记);(b) 留出点逐点误差条;(c) 6787p 已知延迟的注入复现误差。表 1:语义一致性与覆盖统计。图注直接给中位/最大误差与 CXLMemSim 的 7.85%–13.19% 误差带对照 [一手,事实清单]。

**已有数字(出处):** 6 断点曲线与解析模型偏差表(docs/proofs/2026-08-11-cd8p-vmem-tuning.md [一手]);三个负载的一致性检查(docs/proofs/2026-08-11-hybrid-complete.md [一手]);覆盖决策 10,339 条(docs/proofs/2026-08-11-vllm-exact-live-delay.md [一手])。

**新跑项 / 负责人 / 天数 / 依赖:** ① CD8P 新断点与随机模式采集+重拟合:合作者,2 天,依赖冻结快照(含 PR#3);② 6787p capability inventory + 已知延迟复现:合作者,2 天(inventory 半天),依赖 6787p 访问权限;③ 强制放行开关与对照:合作者,1.5 天,需改代码(小,单开关);④ item 9/10 小对照:合作者,1 天。①②可并行。

**限定:** 标定对象是含页错误与驱动开销的端到端软件路径,不是介质本身 [一手,弱点 5];512 页之外是外推,图上浅色底纹;CD8P/CXL SSD 是代理不是 HBF。

**降级路径:** 6787p 形态若只呈现块设备或拿不到 → E1-c 换成 CD8P 上的第二条独立路径(不同文件系统/直接 io_uring)复现;随机模式若采不完 → 只报顺序留出点,随机保留为「按单页计,无实测依据」的显式限定(现状照写,不许隐藏)。

### E2 三模式成本拆账与选择指南

**审稿人问题:**「达到这个保真度要付出多少?我为什么不总用最高精度?」——这正是用户 eq2 的担心:「这3个模式运算时间/成本差异会有显著性吗」。

**回答显著性担心(先用已有数字,再用最小 PoC):** 同一确定性 Qwen3-30B-A3B 用例,基线 0.269996 s、fast 2.014352 s、reference 44.469084 s [一手,docs/proofs/2026-08-11-hybrid-complete.md 与 vllm-exact-live-delay.md]——三档相差 7.5x 与 165x,而这是在只建模 24/2,304 次启动、16 KiB 覆盖下测出的。成本随建模请求数近线性增长是可推的:全专家注册下每 token 884,736 次页访问 [转述,prefetch-accuracy-sweep],比 24 次高四个量级,reference 档外推到不可用。**最小 PoC:** 同一用例取 3 档覆盖(16 KiB / 单专家 / 全层),三模式各跑一次,画「建模请求数 × 三模式墙上时间」——若曲线如预期分叉,tradeoff 论题成立且有「小负载跑 reference、大负载跑 hybrid」的量化选择线,正是用户说的「最理想情况我们可以argue小模型跑最高精度, 大模型跑快速节省时间」。引用 164.70x 时必须写明:reference 验证默认 time_scale=100 是这个头条数字的来源之一 [转述,spec L420];建模介质延迟与每 warp 请求路径开销未分离 [一手,弱点 6]。

**子实验:** E2-a 时间四拆(modeled/wall/service/overhead 四计数器,item 12 的拆分做到计数器能支持的程度,拆不开的部分照 Q3 的说法原样写限定);E2-b 覆盖 × 模式的成本曲线(上述 PoC);E2-c hybrid 旋钮扫描:热身请求数(现 1,024)与稳态抽样率(现 1%)各 3 档,对照 CXLMemSim 的 PEBS 采样周期实验形态 [一手核实于 brief-2 §2];E2-d 纯插桩开销:0.8898 s 对 1.4156/1.8269 s(慢 37–51%)[一手,docs/proofs/2026-08-11-vllm-timing-adapter.md]。

**图表:** 图 3 左:时间拆分堆叠条;右:误差(取 E1 留出误差)× 墙上时间的散点,reference/fast/hybrid 各档一点,Sieve 的误差—加速平面画法 [一手核实于 brief-2 §10(c)]。

**新跑项 / 负责人 / 天数 / 依赖:** 覆盖 3 档 × 3 模式 PoC:合作者,1.5 天,依赖 item 14(扩 vLLM 覆盖到单专家粒度——若全层不可行,取可行的最大档,弱点 4 的 16 KiB 与 61 GB 差距的说法随图写);hybrid 旋钮扫描:合作者,1 天。

**限定:** 墙上时间刻画的是模拟器,不是 HBF 硬件投影(README 自注原句照引 [一手]);两路径间无一致性检查代码 [转述,16-questions #4]——E2 只声称成本差异与旋钮效应,不声称两路径结果可互换,大纲里三处「可检验的一致性」许诺要改口径(见映射表)。

**降级路径:** 覆盖档做不齐 → 用已有的 16 KiB 一档 + 插桩开销数字 + 请求数线性外推的理论估算成文(用户明示接受「理论估算 or 最小poc」)。

### E3 已发表 HBF 假设在同一执行框架下的重演(基准化的旗舰)

**审稿人问题:**「社区为什么需要这个平台?已经有 FlashAccel/TileLens 那些评估了。」

**设计:** 公开文献对同一类器件的参数互相打架:tR 从 4 µs(FlashAccel,沿 XL-Flash,SLC)到 20 µs(Micron,称与 H3 一致),TileLens 扫 1–20 µs,li2026 扫 8–30 µs(TLC);带宽从每堆 460 GB/s(HAVEN)到每 GPU 8 TB/s(Micron);FlashAccel 每 die 96 plane、匹配 4.8 TB/s 需 4,916 个 plane 并发读 [以上均一手核实于 brief-1]。而我们的核心主张恰好是:HBF 带宽是模拟的输出不是查表可得,阵列侧速率取决于规范没给数值的并行读出单元数 N,按 Table 3 组织算出 262.1 至 52.4 GB/s,比接口值低 11.7–58.6 倍 [一手,15 号文件]。E3 把这两件事合成一个实验:

- E3-a **N × tR 二维扫描**(15 号 item 1,blocking;Q10):N ∈ {256, 1024, 3000, 15000},tR ∈ {1, 2, 4, 5, 10, 20 µs},报稳态阵列带宽与端到端吞吐。**在这张二维图上把每篇已发表论文的工作点标出来**:FlashAccel(4 µs)、TileLens 头条点(5 µs)、Micron(20 µs)、OCP 规范包络(profile 按公布数字重锚定,item 15,顺手解决弱点 8)。
- E3-b **假设档案重演**:把四篇论文各自的参数组合做成命名器件档案(flashaccel-like.json、micron-like.json 等,每个值带出处注释),在同一真实负载(Qwen3-30B-A3B 确定性用例)下逐档跑,报同一负载在不同已发表假设下的吞吐差距,并回答:哪些已发表结论对参数选取稳健,哪些会翻。可对表的外部锚点现成:TileLens「20 µs 时连 tile-major 也慢到 3–4×」[一手核实于 brief-1 §2(e)];li2026「介质延迟改善 3.75× 只动端到端 <1%」(其唯一可不加限定引用的单变量组 [一手核实于 brief-1 §5(d)])。
- E3-c **排序不变性**:E3-b 的档案排序在 fast 与 reference(抽样代表点)两档下各算一遍 Spearman/Kendall——便宜档保序,才敢让别人拿快速档当日常对照基线。

**图表:** 图 4(旗舰图):N × tR 平面的吞吐等高线,已发表论文工作点用带引文标记的点标出,外推区浅色底纹。图 5:同一负载在各命名档案下的吞吐条形图,dense 与 MoE 负载分成两组(为 E4 铺垫);小表报两种模式下的排序相关系数。

**已有数字:** 上述核心主张的 262.1–52.4 GB/s 推算 [一手,15 号文件];各论文参数 [一手核实于 brief-1];MQSim 介质基准 4096 请求修复后 p50 659,840 ns、带宽 50.9 GB/s [转述,PR#3 对照数字]。

**新跑项 / 负责人 / 天数 / 依赖:** ① N × tR 扫描:合作者,3 天——**item 1 依赖不存在的代码 [一手,事实清单]**,首选在实验分支已有的页粒度 HBF 回放时序引擎上实现 [一手,git log;内容转述],绕开在 live 路径上改 MQSim;② 档案重演 + 排序:合作者,2 天,依赖 ① 与 item 15(重锚定,0.5 天);③ 全部依赖冻结快照(PR#3 已含)。QD>16 的旧颗粒几何数字按事实清单要求重跑或降入附录 [推断+一手]。

**限定:** 重演的是「该论文的器件参数装进我们的框架」,不是复现该论文的完整系统(FlashAccel 有自己的调度与布局优化,我们不搬);回放引擎跑的档案标明 replay,与 live 数字不混报;每个档案值逐条带出处,缺出处的格写「缺,需合作者从原文补」。
**降级路径:** N × tR 全网格做不完 → 缩成 N 两档 × tR 三档,已发表工作点必须保住;live 路径做不上 → 全部走回放引擎并整节标明 replay;排序不变性做不完 → 只报 fast 档排序,相关系数留作 artifact 复算项。

### E4 真实专家路由下的 dense/MoE 适用范围

**审稿人问题:**「HBF 到底适合哪类模型?你比 trace 论文多知道什么?」

**设计:** 三层先例的共同缺口是没有一层在真实硬件上带真实专家路由测过——TileLens 的 trace 真但时序是模拟,li2026 与 Micron 的专家行为全靠假设 [一手核实于 brief-1 综合判断]。我们的增量:真实执行中哪些专家真被激活、何时读、读多少字节,不需要假设。
- E4-a 真实路由 vs 独立均匀假设:实测每 decode 步的专家并集与 `1−(1−k/E)^B` 对照(paper/37 那张推算表自标「全部是推算」[一手],E4 用真轨迹把它换成实测),扫实际并发 1/8/32。
- E4-b dense 对照两个:容量匹配与激活计算量匹配(不做这两个对照,「MoE 更适合 HBF」的因果分不开——这一点 C0 已论证,保留)。
- E4-c 与外部锚点对表:TileLens 同模型 Qwen 的「MoE 因路由始终 memory-bound,Llama 在 batch 256 转 compute-bound」[一手核实于 brief-1 §2(e)];Micron 的「只有 MoE 专家卸载才让 HBF 被用到」[一手核实于 brief-1 §4(e)];li2026 的大 MoE ΔE2E +280–285% 对小 dense +184.1%(引用必带非单变量限定与容量账缺口 [一手核实于 brief-1 §5(e)])。

**图表:** 图 6:实测专家并集覆盖率 × 并发,叠画独立均匀假设线;dense 两对照同图。一小段文字给出条件式结论(适用范围写成有条件判断)。

**已有数字:** 每 token 884,736 次页访问、384 页(0.04%)不可预测 [转述,prefetch-accuracy-sweep];实验分支已有真实 Qwen MoE 专家轨迹捕获与冻结的 E5 矩阵 [一手,git log;内容转述,需核查代理确认]。

**新跑项 / 负责人 / 天数 / 依赖:** 并发 3 档轨迹采集与并集统计:合作者,2 天,依赖实验分支轨迹工具;dense 对照两跑:合作者,1.5 天。预取(item 2/Q9、PR#5)不进 E4 时序结论——投机预取的运行时收益主张已撤回,门槛原话「在投机读被接进时序引擎之前,不得据此写任何关于运行时快慢的结论」[转述,paper/36:76];流量口径数字(命中率 17.97%→89.16% 等)最多作描述性一句并带口径限定。

**限定:** 单模型(Qwen3-30B-A3B)+两个 dense 对照,结论范围写明;并发是实测 active sequences 不是配置上限(采 C0 的修正)。
**降级路径:** dense 对照做不完两个 → 只做激活计算量匹配的那个,容量匹配改为引用 li2026 数字带限定;E4 整体做不完 → 缩成 E3 图 5 的 dense/MoE 分组条形图加一段分析(仍满足「倒数实验是 dense/MoE 洞察」的最低形态)。

**11 天排期(合作者执行,均可并行两线):** 第 1 天 Gate:冻结快照 + 6787p inventory。第 2–4 天:E1-b/c/d 与 E2 PoC 并行。第 4–8 天:E3-a/b(最长杆)。第 6–9 天:E4。第 9–10 天:E3-c 排序、补图。第 10–11 天:缓冲与降级决断点(第 8 天晚检查 E3-a,不成即启动降级)。

## (b) 微基准怎么论证可信:完整链条

用户原话:「我们做了很多micro benchmark, 但是如何用这些Micro benchmark来论证我们的实验的模拟器是准确的? 我还没想好」。D2 的答案是把 10 篇模拟器论文共有的四步链条(brief-2 综合二,[一手核实于简报])落到我们的件上,并加一条基准工具特有的第五步:

1. **标定/提取(微基准产参数):** CD8P vmem 曲线的标定子集(3 断点)产出端到端 vmem 档;6787p 介质实测产出第二个档。每个档参数带出处三分类(实测/有出处/建模),照 li2026 的标注纪律 [一手核实于 brief-1 §5(d)]。
2. **机制级验证(微基准对真值,误差最小的一层):** 留出断点 + 新尺寸 + 随机模式对 CD8P;已知延迟复现对 6787p。这一步回答「注入机器本身准不准」,与「参数取值对不对」分开——Quartz 的分离写法:机制可验证,参数明说是投影 [一手核实于 brief-3]。先例误差量级作对照:FEMU 微基准 0.8–11.6%、MQSim 合成负载 2.9/4.9% [一手核实于 brief-2]。
3. **组合级验证(应用对真值,误差变大且要归因):** 完整 Qwen3 用例作应用级留出,报归一化减速误差并分解残差(插桩、服务路径、建模延迟三块,E2-a 的拆账在这里复用)。先例:FEMU 宏观 0.5–38% 并按线程×plane 归因;MQSim 真实 trace 6–18% [一手核实于 brief-2]。MQSim 的验证背书只覆盖「给定介质时序下的排队/调度行为」,介质时序对 HBF 是否成立正是我们标定补上的那块——这句写进正文,把 reference 路径的可信度接到 MQSim 的 FAST'18 验证上而不冒领。

## (d) 与 C0 的差异点清单及理由

1. **旗舰实验换位:C0 的 EQ3 是「我们自己回答一个设计问题」(ρ × 服务率可行域相图),D2 的 E3 是「把别人的假设放进我们的框架重演」。** 理由:两者都展示研究效用,但基准化的判据是「别人以后会不会用」。可行域相图是一次性结论,读者引用的是结论;假设重演图上每个点都是一篇已发表论文,读者引用的是平台——后续任何 HBF 论文选 tR/N 时,这张图是现成的定位坐标系,器件档案以论文命名可直接复用。已发表参数互相打架(tR 差 5 倍、带宽差 17 倍、每比特能耗差约 4 倍 [一手核实于 brief-1 综合判断第 2 条])是客观存在的社区痛点,C0 没有利用它。
2. **排序保真从 EQ1 门槛表里的一行升为贯穿性主张(E1→E2→E3 的链条)。** 理由:C0 把 rank ≥0.90 列为措辞门槛之一;D2 把「便宜档保序」作为基准工具的核心卖点单独验证并成图。对照基线要被日常使用,用户用的必然是 fast/hybrid 档,别人信的必须是「这档做比较不会反」。
3. **温度:C0 是有条件保留的 EQ4,D2 直接移出主问题。** 理由:判据次序裁定温度为次要;运行时 0 命中 [一手] 加 11 天工期,「有条件保留」在执行上等于占着页数与 Gate 6 的一个不会通过的条件。D2 把腾出的页数与天数给 E3。代价与 ASK 见上节。
4. **EQ1 规模裁剪:C0 的 EQ1 五个子实验含 8 档 QD × 多模式 × 多尺寸的全网格;D2 的 E1 收缩到留出验证 + 两锚点 + 三个小对照。** 理由:11 天里 E1 全网格与 E3 旗舰不能兼得;可信度的说服力在「留出 + 双锚点 + 诚实限定」的结构,不在网格密度(Cylon 全文没有一个百分比误差数字仍过了 FAST [一手核实于 brief-2 §1])。裁掉的维度逐条写进「已验证范围」表,不冒领。
5. **eq2 的回答方式:C0 列九组对照拆四段时间;D2 用「覆盖档 × 模式」的最小 PoC 直接回答显著性本身。** 理由:用户担心的不是拆分不细,是「时间都差不多则论题不成立」;已有 0.27/2.01/44.5 s 三个数说明在 16 KiB 覆盖下已差两个量级,PoC 只需证明差距随覆盖增长,比九组对照便宜且正中问题。
6. **基准平台要素显式分箱:** D2 明确列出正文放公平性契约/真值声明/claim 门槛/切分声明四件,档案套件、轨迹、参考结果、manifest、CSV、脚本全进 artifact,并把「以论文命名的器件档案」定为 artifact 的第一交付物。C0 §1.2 列了同一批要素但未分箱、无命名档案概念。
7. **保留 C0 的部分(不为不同而不同):** 冻结快照与 PR 集成纪律(Gate 0/问题 E)、公平性契约措辞(§1.2)、claim 门槛表(§6.8)、实际 decode 并发替代配置上限(§8.6)、dense 双对照(§8.4)、统计规范(§12)、参考文献与借鉴点(§17)全部原样采用。

**D2 的主要风险(自报):** E3-a 依赖的代码不存在,回放引擎降级会让旗舰图带 replay 标签,削弱「真实执行」卖点——这是 D2 相对 C0 多担的一份执行风险,换来的是基准化上限。第 8 天的降级决断点就是为它设的。
